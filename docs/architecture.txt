TANGER — MODULAR TUTORIAL FOUNDATION

  npm ci
  npm run dev

Use Node 22.12+. The app opens an original title screen. Play loads the authored
tutorial area and its GLB models, then starts a local training session. Loading
can be cancelled or retried. Escape pauses; settings work from title or pause.
No settings, saves, or progress are persisted. All branding in-game is TANGER.

OWNERSHIP AND DEPENDENCIES

core/         Pure math and fixed-step scheduling.
content/      Tutorial drills, combat tuning, settings definitions/defaults.
world/        Area schema, inferred types, validation.
game/         Platform-independent movement/collision, combat, tutorial state.
application/  Ports, source loading, real-time scheduling and session orchestration.
adapters/     DOM/input/audio and Three.js asset/rendering implementations.
main.ts       Composition root, screen transitions, loading cancellation/lifecycle.
scripts/      Original model authoring/export and area validation/schema tools.
public/       Editable authored areas and original art/model assets.

Core/game code cannot import Three.js, the DOM, or browser audio. Only the schema
module imports Zod. Three dependencies/addons are limited to the renderer adapter.
Architecture tests enforce inward imports and prevent cross-adapter dependencies.

AREA AND MODEL LOADING

public/areas/tutorial.area.json supplies static model instances, colliders, and
named spawn/marker/target anchors. Asset paths are relative to the public content
root. No map geometry is constructed in the game renderer. GLBs are fetched,
parsed, cached, and cloned by AssetLibrary; the operator and unit are animated
views of simulation state. Model asset IDs currently select the tutorial actors.

Edit area data without rewriting simulation or renderer code. The controller
currently supports grounded motion against axis-aligned box colliders. Other
schema collider shapes are reserved for a future physics adapter and fail clearly
in this controller. Sector streaming, traversal modes, and general rigid-body
physics are future work; do not present the tutorial as a finished open world.

  npm run area:validate -- public/areas/tutorial.area.json
  npm run area:schema
  npm run assets:build

The editor JSON Schema and TypeScript types derive from area-schema.ts. CLI/runtime
validation adds reference, bounds, and quaternion checks. These are loading and
authoring diagnostics, not a centralized competitive data-integrity system.

TIME AND COMBAT

GameSession collects input edges across render frames until a fixed simulation
step consumes them once. The simulation runs at 60 Hz with bounded catch-up.
Combat has windup/contact/recovery, a three-hit sequence, limited input buffering,
dash cancellation/cooldown, and a telegraphed training-unit attack. The tutorial
contains five short drills and free practice after completion.

Real time drives input, cooldowns, dash movement, impact timers, and screen controls.
Impact freezes then slows the combat timeline; missed attacks do not slow time.
Pause discards elapsed wall time and pending input edges. Hidden/unfocused windows
pause rather than progressing unattended. Rendering interpolates player positions
and owns procedural joint animation, bloom, camera feedback, and combat indicators.

RESOURCE OWNERSHIP

The renderer owns GPU resources, cached model instances, environment maps, effect
passes, and resize/context listeners. Audio and input adapters own their listeners
and audio context. Main cancels loading, animation frames, and adapter resources
on hot reload. Completed cancelled GLB parsing releases its resources.

COMMUNITY SERVERS

The user's intended long-term architecture is self-hosted/community-hosted servers.
No server runtime or transport exists yet. Keep simulation/state portable so a
future server can own world rules. Do not silently introduce managed accounts,
cloud persistence, global progression ownership, or anti-cheat infrastructure.
