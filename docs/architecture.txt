TANGER — INFRASTRUCTURE GUIDE

Run with Node 22.12+:
  npm ci
  npm run dev

The application opens an empty viewport with "No area loaded." There is no default
map, floor, player, movement, gameplay HUD, persistence, or animation loop. It draws
once and redraws on resize/context restoration. No game content is being designed.

MODULE OWNERSHIP

core/         Reusable platform-independent timing. Not active in the empty app.
world/        Area interchange schema, inferred types, and pure parsing/validation.
application/  Ports and a loading operation: source text -> validation result.
adapters/     Concrete platform implementation. Currently the empty Three viewport.
main.ts       Browser composition root; does not hardcode or load an area.
scripts/      Local file validation and generated editor-schema tooling.

Future content/ and game/ modules can hold authored definitions and gameplay rules
when those features are requested. The old prototype implementations were removed.

Dependencies point from adapters/application to world/core. Only the schema module
imports Zod; only the Three adapter imports Three.js. Architectural tests reject
browser globals in pure modules and cross-adapter imports. Loading is separate
from activation: a validated area does not implicitly create GPU/physics resources.

AREA DATA

src/world/area-schema.ts is the canonical versioned format. TypeScript types and
public/schemas/area.schema.json derive from it. parse-area.ts checks structure,
IDs, references, bounds, and rotations. Errors include field paths. There are no
engine objects or embedded hardcoded meshes in an area document.

  npm run area:validate -- path/to/document.area.json
  npm run area:schema

The format accepts model instances, independently authored collision shapes,
sector bounds, anchor points, and graph connections. Sector geometry is not tied
to a square terrain grid. See docs/area-format.txt for exact authoring conventions.
No real area files or model assets are supplied. Tests use synthetic parser input.

loadArea accepts an injected AreaSourcePort and optional cancellation signal. It
returns a validated document or issues; the browser does not call it yet. Future
filesystem/network/editor sources can implement the port independently of parsing.
GLB decoding, actual asset existence checks, streaming, and activation remain to
be implemented once real content is supplied. Neither a physics engine nor combat
has been installed. See docs/research.txt for sourced technical research.

CHECKS

  npm run check
  npm run build
  npx playwright install chromium   (first browser test setup)
  npm run test:e2e

Checks cover rejected documents, valid references, parser diagnostics, source
failures/cancellation, CLI exit behavior, schema drift, timing, and dependency
boundaries. Browser checks verify zero scene objects and no storage access.

There are no font/CDN/runtime content requests, storage reads/writes, or API keys.
Markdown files are ignored and no README is included. Local Git author/committer
identity is configured as BZ110 using the supplied GitHub noreply address.
